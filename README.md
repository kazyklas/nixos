# ❄️ nixos

**One flake. A whole desktop.**

A declarative NixOS + Home Manager configuration for a Hyprland workstation —
Lua-configured compositor, [Noctalia](https://noctalia.dev) shell, a Neovim built
from Nix, and Claude Code wired in deep enough that it has its own chat panel in the bar.

`Hyprland` · `Noctalia` · `Home Manager` · `nixvim` · `Spicetify` · `Claude Code`

</div>

---

## What this is

Everything about these machines — bootloader, kernel params, LUKS root, the window
manager's keybinds, the Spotify theme, the Neovim LSP set, even the AI assistant's
skills — lives in this repository as Nix expressions. A fresh machine is one
`nixos-rebuild switch` away from being *the* machine; nothing is configured by hand,
and nothing drifts.

One flake describes every host: `laptop` and `beast` share `configuration.nix` and
`home.nix` verbatim and differ only in their `hosts/<name>/` directory — see
[Hosts](#hosts).

It is a personal config, not a framework. But the interesting parts are stolen-from
on purpose — see [Highlights](#highlights).

## Highlights

### 🪟 Hyprland, configured in Lua — from Nix

[`modules/hyprland.nix`](modules/hyprland.nix) targets Hyprland's modern Lua config
backend (`configType = "lua"`), so binds are generated rather than typed. Directional
focus/swap and all ten workspace binds come out of two `concatMap`s instead of forty
hand-written lines:

```nix
bind = keys: dispatcher: { _args = [ keys (mkLuaInline dispatcher) ]; };

focusBinds = lib.concatMap (d: [
  (bind "SUPER + ${d.key}"         ''hl.dsp.focus({ direction = "${d.dir}" })'')
  (bind "SUPER + SHIFT + ${d.key}" ''hl.dsp.window.swap({ direction = "${d.dir}" })'')
]) directions;
```

### 🖥️ Monitor profiles that switch without a rebuild

Screens are per-machine data, so the layouts live in `hosts/<name>/home.nix` as
plain attrsets under `my.hyprland.monitorProfiles` — four named desks on the laptop
(`work`, `home`, `solo`, `docked`). From them the module generates a
`monitor-profile` shell application that
applies a layout at runtime through `hyprctl eval`, remembers the choice in
`$XDG_STATE_HOME`, and restores it on the next login — so moving between desks is a
keystroke, not a `switch`. Outputs a profile doesn't mention are explicitly disabled,
so no phantom screen ever holds a workspace hostage.

```
SUPER + SHIFT + M        pick a profile with rofi
SUPER + ALT + 1/2/3      work / home / solo
```

`SUPER + ALT + n` is generated from the host's `quickProfiles` list, and a host that
declares no profiles at all gets no tool, no binds and no `monitor` entries — it just
lets Hyprland auto-configure whatever it finds, which is what a machine does before
anyone has written its output names down.

### 💬 Claude, in the shell bar

[`modules/noctalia-plugins/claude_chat/`](modules/noctalia-plugins/claude_chat/) is a
Noctalia plugin written in Luau: a floating chat panel with **multiple concurrent
conversations**, streamed live from the Claude Code CLI — so it reuses the existing
`claude` login, with no API key and no second bill. Transcripts and session ids persist
across restarts; a turn keeps streaming while you read another thread.

```
SUPER + A                toggle the panel
```

It is symlinked out of the repo with `mkOutOfStoreSymlink`, which means Noctalia
hot-reloads `.luau` edits in the running shell — develop the plugin without rebuilding
the system. Full docs: [plugin README](modules/noctalia-plugins/claude_chat/README.md).

### 🤖 A declaratively managed AI assistant

`~/.claude` is generated by `programs.claude-code` from
[`modules/claude/`](modules/claude/), one directory per skill, auto-discovered via
`readDir` — adding a skill is creating a folder. The repo ships a
[`nixos-claude-code`](modules/claude/skills/nixos-claude-code/SKILL.md) skill that
teaches Claude how to edit *this* config correctly, so the assistant extends its own
configuration the idiomatic way. `settings.json` is deliberately left mutable, because
Claude Code writes to it itself.

### ✍️ Neovim as a build artifact

[`modules/nixvim.nix`](modules/nixvim.nix) — Telescope, Treesitter, nvim-tree, gitsigns,
LazyGit, cmp, conform (format-on-save) and LSP for Lua, Python (pylsp + ruff), Bash, Nix
(nixd), Docker and Terraform. Tokyo Night, transparent, no plugin manager, no lockfile
drift.

### 🎵 A terminal-looking Spotify

Spicetify-patched Spotify with the `text` theme, Tokyo Night colors, JetBrains Mono Nerd
Font, square corners, cover art off, ASCII banner on — plus adblockify, hidePodcasts and
the marketplace. The input pins its own nixpkgs on purpose: `spicetify-cli` has to match
the Spotify build it patches.

### 🔌 Pragmatic escape hatches

When upstream is broken or just missing from nixpkgs, the fix is in-tree and documented:
[`pkgs/opencode-bin.nix`](pkgs/opencode-bin.nix) builds `opencode` from the upstream
prebuilt release because the nixpkgs source build of 1.18.30 fails on every prompt.
Likewise Zen Browser is wrapped from its AppImage, and
[`pkgs/future-cyan-hyprcursor.nix`](pkgs/future-cyan-hyprcursor.nix) vendors the
[Future Cyan](https://gitlab.com/Pummelfisch/future-cyan-hyprcursor) Hyprcursor theme
from its GitLab repo, since it isn't packaged in nixpkgs either. Each workaround carries
a comment saying exactly why it exists — so it can be deleted the day it stops being
needed.

## Layout

```
.
├── flake.nix                     inputs, the mkHost helper, one output per host, Cachix for Noctalia
├── configuration.nix             SHARED system: boot, kernel, network, audio, fonts, podman, libvirt
├── home.nix                      SHARED user: packages, zsh, git, fzf, kitty, spicetify, caelestia
├── .github/workflows/ci.yml      CI: evaluates every host's nixosConfiguration on each PR
├── hosts/
│   ├── laptop/
│   │   ├── default.nix           hostname, stateVersion, pulls in modules/laptop.nix
│   │   ├── hardware-configuration.nix   generated: LUKS root, Intel CPU, kvm-intel
│   │   └── home.nix              the four monitor profiles
│   └── beast/
│       ├── default.nix           hostname, stateVersion, the NVIDIA block
│       ├── hardware-configuration.nix   placeholder until generated on the machine
│       └── home.nix              monitor profiles (empty until first boot)
├── modules/
│   ├── laptop.nix                battery, lid, deep suspend, power-profile switching
│   ├── hyprland.nix              compositor config in Lua + the monitor-profile tool
│   ├── nixvim.nix                Neovim
│   ├── claude-code.nix           ~/.claude generation
│   ├── claude/skills/            one dir per Claude Code skill, auto-discovered
│   ├── noctalia-claude-chat.nix  symlinks the plugin into the shell's plugin dir
│   ├── hermes-agent.nix          programs.hermes-agent (Hermes Agent CLI + desktop)
│   └── noctalia-plugins/
│       └── claude_chat/          the Claude chat panel (Luau)
└── pkgs/
    └── opencode-bin.nix          opencode from the upstream binary
```

## Hosts

| Host | Attribute | Hostname | What it is |
|---|---|---|---|
| laptop | `#laptop` (also `#nixos`) | `nixos` | Intel laptop, LUKS root, four desks |
| beast | `#beast` | `beast` | desktop, NVIDIA — not installed yet |

The rule for where a setting goes:

- **true of every machine** → `configuration.nix` (system) or `home.nix` (user).
  Packages, shell, editor, Claude Code skills, keybinds, theme: all shared, so both
  machines feel the same.
- **true of one machine** → `hosts/<name>/default.nix` (system) or
  `hosts/<name>/home.nix` (user). Hostname, `stateVersion`, GPU, screens.
- **true of a *kind* of machine** → a module in `modules/` that only those hosts
  import, like [`modules/laptop.nix`](modules/laptop.nix) for the battery, the lid
  and deep suspend.

`hosts/laptop/` keeps `networking.hostName = "nixos"` on purpose — the flake
attribute is what got renamed, not the machine, so Tailscale and SSH `known_hosts`
never noticed. `nixosConfigurations.nixos` is kept as an alias of `laptop` so the
bare `nixos-rebuild --flake ~/nixos` (which resolves the attribute from the
hostname) still works.

**Adding a third machine** is two steps: create `hosts/<name>/{default.nix,
hardware-configuration.nix,home.nix}`, then add `"<name>"` to the list in
`flake.nix`:

```nix
nixosConfigurations = nixpkgs.lib.genAttrs [ "laptop" "beast" ] mkHost // { … };
```

Add the same name to the `matrix.host` list in
[`.github/workflows/ci.yml`](.github/workflows/ci.yml) so CI validates it too.

## CI

[`.github/workflows/ci.yml`](.github/workflows/ci.yml) runs on every pull
request against `main`: one job per host, each evaluating
`nixosConfigurations.<host>.config.system.build.toplevel` with Nix flakes, so
a PR can't merge without proof that it still evaluates for both `laptop` and
`beast`. It only evaluates (module options, asserts, the derivation graph),
not builds packages — much faster, and enough to catch a broken module.

### Installing beast

```sh
# 1. in the installer: partition, encrypt, mount to /mnt, then
nixos-generate-config --root /mnt

# 2. put the generated hardware config in the repo (replacing the placeholder,
#    whose `warnings` line reminds you on every build that it is still there)
git clone <this repo> /mnt/home/tklas/nixos
cp /mnt/etc/nixos/hardware-configuration.nix /mnt/home/tklas/nixos/hosts/beast/
cd /mnt/home/tklas/nixos && git add hosts/beast/hardware-configuration.nix

# 3. install
nixos-install --flake /mnt/home/tklas/nixos#beast
```

After the first boot: uncomment the NVIDIA block in `hosts/beast/default.nix`, fill
in `hosts/beast/home.nix` with the monitor layouts from `hyprctl monitors`, and
`noctalia msg plugins enable tklas/claude_chat`.

### Keys worth knowing

| Bind | Action |
|---|---|
| `SUPER + Return` | terminal (`footclient`) |
| `SUPER + Space` | Noctalia launcher |
| `SUPER + A` | Claude chat panel |
| `SUPER + h/j/k/l` | focus (`+ SHIFT` to swap) |
| `SUPER + 1…0` | workspace (`+ SHIFT` to move window) |
| `SUPER + Q` / `T` / `F` | close / float / fullscreen |
| `SUPER + S` | magic scratchpad |
| `SUPER + W` | toggle wallpaper |
| `SUPER + C/V/X` | universal copy/paste/cut (works in terminals too) |
| `PRINT` | region screenshot (`+ SUPER` for the whole output) |
| `SUPER + CTRL + L` | lock |

Power management is automatic on the laptop ([`modules/laptop.nix`](modules/laptop.nix)):
udev rules flip `power-profiles-daemon` to *performance* on AC and *power-saver* on
battery. `nix.gc` prunes the store weekly on every host.

## Using it

> [!NOTE]
> This config hardcodes the user `tklas`, and each `hosts/*/hardware-configuration.nix`
> describes one specific machine. Treat it as a reference to read and lift from rather
> than something to apply to your own machine unchanged.

```sh
# Rebuild the system (system + home-manager in one go)
sudo nixos-rebuild switch --flake /home/tklas/nixos#laptop
sudo nixos-rebuild switch --flake /home/tklas/nixos#beast

# Preview without activating
nixos-rebuild build --flake /home/tklas/nixos#laptop

# Build a host from the other host (same flake, same lock, so it matches)
nixos-rebuild build --flake /home/tklas/nixos#beast

# Update inputs
nix flake update                    # everything
nix flake update nixpkgs noctalia   # just these
```

Flakes only see **git-tracked** files — `git add` new files before rebuilding, or Nix
will not know they exist. This is the single most common reason a new module or skill
"doesn't show up".

The Noctalia Claude Chat plugin needs a one-time enable:

```sh
noctalia msg plugins enable tklas/claude_chat
```
